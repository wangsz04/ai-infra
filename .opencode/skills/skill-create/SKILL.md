# skill-create

## 目录结构

一个skill的目录结构如下：

```markdown
xxx-skill/ // 技能目录，**必须**使用kebab-case命名，且与技能名称`name`一致
├── SKILL.md // 技能主文件
├── README.md // 技能说明文档(可选，如果技能比较复杂，可以有一个详细的说明文档)
├── examples/ // 使用示例文件夹(可选，包含技能提供的参考示例)
├── assets/ // 资源文件夹(可选，包含技能提供的参考的资源)
├── references/ // 参考资料文件夹(可选，包含技能提供的参考的资料)
```

## SKILL.md规范

### frontmatter规范

必须以 YAML frontmatter 开头。
仅包含以下字段：

- name（必填）:skill-name // 技能名称，与文件夹名称一致，必须使用小写字母数字和连字符，不能包含空格和特殊字符, 等效表达式：`^[a-z0-9]+(-[a-z0-9]+)\*$`
- description（必填）: 技能描述，简要说明技能的功能和用途，字数限制在150字以内
- license（可选）
- compatibility（可选）: opencode
- metadata（可选，字符串到字符串的映射）: // 可选，字符串到字符串的映射，包含技能的额外信息，例如版本、作者等
  例如：

```yaml
metadata:
  version: 1.0.0
  author: wangsz
```

### SKILL.md内容规范

- 整体要求：清晰、简洁、有条理性，划分层级，重点明确，避免冗长和重复，理论**不超过150行**, 超出应考虑使用`references/`, `assets/`, `examples/`。
- 语法要求: **必须**使用 Markdown 语法，合理使用标题、列表、代码块等格式来组织内容。
- 标题要求：使用Markdown **1-3级标题**，分层表述，尽量不超过 4 级标题。
- 自然语言要求: 除非必要，技能内容应使用**简体中文**撰写。

### 代码示例规范

- 示例代码分类: 简单示例(10行以内), 复杂示例(10行以上)
- 注释规范: 所有代码**必须**添加适量注释，至少描述其功能和作用，复杂示例还应简单解释其实现原理和使用方法，所有注释必须使用统一的`jsdoc`语法。
- 示例存放规则:
  - 简单示例: 数量少时，可直接内联到主`SKILL.md` 或 `references/`的文件中，数量多时，**必须**按照分类整理为对应文件存放在`examples/`文件夹中，并在相应的文件中进行声明或引用。
  - 复杂示例: **必须**添加适量注释放在`examples/`文件夹中，并在相应的文件中进行声明或引用。

### 引用/参考示例规范

- 存放位置: 所有引用/参考资料**必须**存放在`references/`文件夹中，并**必须**在主`SKILL.md`中使用Markdown引用语法进行声明或引用。
- 格式规范: 所有被引用文件**必须**使用Markdown语法编写，并且**必须**包含标题、描述、链接等基本信息，确保内容清晰、规范、权威、易于理解。
- 内容来源: 引用/参考资料可以使用**WebSearch/CodeSearch/WebFetch**等工具搜索来自官方文档、权威博客、学术论文等可靠来源，确保内容的准确性和权威性。并在末尾注明来源链接。

### 资源示例规范

- 存放位置: 所有资源文件**必须**存放在 `assets/` 文件夹中，并**必须**在主 `SKILL.md` 中使用Markdown引用语法进行声明或引用。
- 格式规范: 资源文件可以是图片、已有的代码等多种形式。

### 操作流程描述规范

- 如需要表述操作流程，**必须**使用Markdown列表+STEP标志格式进行描述，确保步骤清晰、逻辑性强，便于用户理解和操作。
  例如:

```markdown
- **STEP1**: 获取资源
- **STEP2**: 使用函数处理资源
```

## Skill 创建流程

按照以下步骤创建一个TODO List来创建一个新的skill:

- **STEP1**: 检查用户需求, 若用户未提供具体需求, 则使用**Question**工具询问用户的具体需求, 包括但不限于技能名称、技能功能、技能用途, 元数据等。
- **STEP2**: 检查并准备skill 目录, 若用户未提供目标目录, 则使用**Question**工具询问目标目录并给出一个可能的默认值, 使用 **Edit** 工具创建目录。
- **STEP3**: 根据用户需求准备skill 所必须的信息, 必要时根据规则生成`references/`、`examples/`、`assets/`等文件夹和相应的文件，并使用**Edit**工具创建和编辑这些文件，确保它们符合上述规范。
- **STEP4**: 完成skill 创建
